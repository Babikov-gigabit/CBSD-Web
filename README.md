# CBSD Web

Веб-интерфейс для [CBSD](https://github.com/cbsd/cbsd): управление клетками (jail), виртуальными машинами bhyve и Xen, базами FreeBSD, образами и первичной настройкой CBSD из браузера.

Это **надстройка**, а не замена: интерфейс читает собственные базы CBSD (`$workdir/var/db/*.sqlite`) и выполняет все изменения через штатный CLI `cbsd`. Поэтому он сразу подхватывает уже установленный и настроенный CBSD, а всё, что сделано в консоли, видно в интерфейсе, и наоборот.

## Возможности

| Раздел | Что умеет |
|---|---|
| Обзор | нагрузка, память и диск хоста, версия CBSD, параметры узла, счётчики клеток и ВМ, последние задачи |
| Клетки (jail) | список с поиском и статусом, запуск / остановка / перезапуск, создание (IP, hostname, версия базы, VNET, пакеты), клонирование, снимки ZFS, удаление с подтверждением по имени |
| Конфигурация клетки | все параметры `cbsd jset` (около 70) по группам: основные, сеть и VNET, разрешения `allow_*`, файловые системы, SysV IPC, CPU и тайм-ауты, хуки `exec_*`; поиск по параметрам, подсветка изменений, перезапуск для параметров, которые не применяются на лету |
| Лимиты ресурсов | все ограничения `cbsd jrctl` (память, CPU, процессы, файлы, диск, квота, IOPS, SysV и т. д.) и текущее потребление запущенной клетки |
| Терминал | оболочка root внутри запущенной клетки прямо в браузере (`cbsd jlogin` через WebSocket, xterm.js) |
| Снимки ZFS | список с датой, объёмом и занимаемым местом, расположение (набор ZFS и каталог `.zfs/snapshot` с файлами снимка), создание, откат, удаление по одному и всех сразу |
| Схема снимков | линия снимков с объёмом изменений между ними, текущее состояние, ветки (окружения, созданные клонированием из снимка, и исходный снимок, если окружение само клон), история откатов с потерянными снимками; откат с сохранением текущего состояния как новой клетки-ветки |
| Сеть и ресурсы | IP-адреса, интерфейсы окружения на хосте (epair/tap, MAC, мост) с трафиком и текущей скоростью, CPU, память, процессы, место на диске |
| Настройки ВМ | вкладка «Конфигурация» у ВМ bhyve и Xen: параметры `bset`/`xset` с проверкой значений, пароль VNC не показывается, изменения применяются при следующем запуске или сразу с перезапуском |
| Консоль VNC | адрес, порт, пароль и команда SSH-туннеля; консоль ВМ прямо в браузере (noVNC через WebSocket-прокси) |
| ВМ bhyve и Xen | то же самое плюс выбор ОС из ~200 профилей CBSD, облачные образы с cloud-init (IP, шлюз, пользователь, SSH-ключ), CPU/RAM/диск, параметры VNC |
| Базы FreeBSD | список установленных баз и загрузка новой (`cbsd repo action=get sources=base`) |
| ISO-образы | загрузка ISO с компьютера (с прогрессом и проверкой SHA-256) или скачивание сервером по ссылке; образ регистрируется в CBSD (`cbsd media`) и выбирается в поле «Установочный ISO» при создании ВМ; карточка «Установка ОС» на странице ВМ подключает ISO, запускает с него машину и после установки переключает загрузку на диск |
| Журналы | вкладка у клетки или ВМ: `jails-system/<имя>/*.log` (для ВМ — `bstart.log` с командой bhyve и её выводом), строки системного журнала, вывод последних задач; пароли скрыты |
| Образы, Узлы | зарегистрированные образы, диски и узлы кластера |
| Задачи | все долгие операции идут в фоне; вывод `cbsd` транслируется в браузер в реальном времени, задачу можно отменить |
| Установка и настройка | диагностика (CBSD установлен, sudo работает, workdir, initenv, cbsdd, vmm) и мастер `initenv` вместо интерактивного диалога |
| Пользователи, аудит | роли, смена пароля, журнал всех входов и операций |

## Архитектура

```
браузер ──HTTPS──> cbsd-web (Go, пользователь cbsdweb)
                     ├─ чтение:   $workdir/var/db/local.sqlite, nodes.sqlite (read-only, query_only)
                     ├─ профили:  $workdir/etc[/defaults]/vm-*.conf, /usr/local/cbsd/etc/defaults
                     └─ действия: sudo -n /usr/local/bin/cbsd <команда> key=value ...  (без shell)
```

* **Бэкенд** — Go, один статический бинарник (~11 МБ) без cgo и внешних зависимостей во время работы. SQLite через чистый Go-драйвер. Запросы подстраиваются под набор колонок, поэтому работают со старыми и новыми версиями CBSD.
* **Фронтенд** — чистый JavaScript без фреймворков и сборки (~52 КБ, ~15 КБ в gzip), встроен в бинарник, отдаётся из памяти со сжатием и ETag. Тёмная и светлая тема, работает на телефоне.
* **Задачи** — пул с ограничением параллелизма; на одно окружение одновременно выполняется одна операция; при отмене завершается вся группа процессов.

## Безопасность

* Сервер **не работает от root** (отказывается запускаться). Права root даёт только правило sudo на `/usr/local/bin/cbsd` и `initenv` (`deploy/sudoers`).
* `cbsd` вызывается напрямую через `exec`, без shell. Каждое значение проверяется по строгому белому списку (имена, IP, размеры, профили, пакеты), потому что скрипты CBSD подставляют аргументы в shell-код и SQL. SSH-ключ передаётся файлом, а не строкой. Тесты проверяют отказ на `;`, `$()`, кавычках, переводах строк и т. п.
* TLS по умолчанию (самоподписанный сертификат создаётся при первом запуске, отпечаток пишется в лог; можно указать свой). TLS 1.2+ только с AEAD-шифрами, HSTS.
* Пароли — bcrypt (cost 12), минимум 10 символов; защита от перебора (5 попыток → блокировка на 15 минут по IP и по имени); одинаковое время ответа для существующих и несуществующих пользователей.
* Сессии: случайный 256-битный токен, в памяти хранится только его SHA-256; cookie `__Host-`, `HttpOnly`, `Secure`, `SameSite=Strict`; тайм-аут бездействия 30 минут, максимум 12 часов; при смене пароля или роли все сессии пользователя закрываются, понижение роли действует сразу.
* CSRF-токен на каждый изменяющий запрос плюс проверка `Origin` / `Sec-Fetch-Site`.
* Строгий CSP (`script-src 'self'`, без inline-скриптов; inline-стили разрешены только для терминала xterm.js), `X-Frame-Options: DENY`, `nosniff`, `no-referrer`; весь вывод в браузере через `textContent`, без `innerHTML`.
* Роли: **viewer** (просмотр), **operator** (запуск/остановка/создание/снимки, настройки и лимиты клеток), **admin** (удаление, откат снимков, хуки `exec_*`/`mnt_*`, версия и режим базы, терминал, initenv, пользователи, аудит). Окружения с `protected=1` удалить нельзя.
* Терминал и VNC-консоль (и пароль VNC) по умолчанию только для администратора (`terminal_role`), только для запущенных клеток; WebSocket проверяет сессию, CSRF-токен и `Origin`; не больше 4 терминалов на пользователя и 16 всего; закрывается после 30 минут бездействия и при выходе из сессии; открытие и закрытие пишутся в аудит.
* Хуки принимают только путь к скрипту без пробелов и спецсимволов: `cbsd jset` разбивает значения по пробелам и подставляет их в shell.
* Белый список сетей клиентов (`allowed_networks`, по умолчанию локальные и частные сети), лимит тела запроса 64 КБ, тайм-ауты HTTP.
* ISO-образы: загружать, скачивать и удалять может только администратор. Файл пишется самим сервисом (без sudo) потоком на диск во временный файл в `<workdir>/src/iso/upload` и появляется под своим именем только после проверок: имя из безопасного алфавита с окончанием `.iso`, размер не больше `iso_max_size_gb`, хватает места, есть сигнатура ISO 9660/UDF, совпадает SHA-256 (если указан); существующий файл никогда не перезаписывается. Скачивание по ссылке — только http/https, без логина в адресе, не больше 5 перенаправлений; адреса loopback/частных/link-local сетей запрещены (проверяется адрес, к которому реально идёт подключение), пока не включён `iso_fetch_allow_private`. Одновременно не больше двух загрузок; зависшая на 2 минуты загрузка обрывается. Подключённый к ВМ образ удалить нельзя.
* Журнал аудита (JSON lines, `0600`): входы, неудачные попытки, все запуски задач и их результат, изменения пользователей.

> Учтите: кто управляет учётной записью `cbsdweb` или веб-администратором, тот управляет всеми клетками и ВМ хоста. Не открывайте порт в интернет без необходимости: лучше VPN или SSH-туннель.

## Установка

Требуется FreeBSD 13+ (amd64 или arm64).

```sh
# 1. Собрать бинарник (на любой машине с Go 1.24+) или взять готовый из bin/
make freebsd                     # -> bin/cbsd-web-freebsd-amd64, bin/cbsd-web-freebsd-arm64

# 2. Скопировать каталог на сервер и запустить установщик от root
sh scripts/install.sh            # ставит cbsd и sudo, создаёт пользователя cbsdweb,
                                 # конфиг, sudoers, rc.d, первого администратора
```

Установщик печатает пароль `admin` — сохраните его и смените в разделе «Учётная запись». Затем откройте `https://<ip-сервера>:8443/`. Если CBSD ещё не инициализирован, перейдите в «Установка и настройка» и запустите мастер.

Вручную: `cbsd-web useradd NAME -role admin|operator|viewer`, `cbsd-web users`, `cbsd-web userdel NAME`, `cbsd-web check`.

## Подключение к уже установленному CBSD

Ничего переносить не нужно. `workdir` определяется из `cbsd_workdir` в `/etc/rc.conf` (обычно `/usr/jails`); если CBSD установлен в другое место, укажите `"workdir"` и `"dist_dir"` в `/usr/local/etc/cbsd-web/cbsd-web.conf`. Если у вас несколько рабочих каталогов, запустите по экземпляру интерфейса на каждый (разные порты и конфиги).

## Конфигурация

`/usr/local/etc/cbsd-web/cbsd-web.conf` (JSON, пример в `deploy/cbsd-web.conf.sample`):

| Ключ | По умолчанию | Описание |
|---|---|---|
| `listen` | `127.0.0.1:8443` (установщик ставит `0.0.0.0:8443`) | адрес и порт |
| `tls_auto` / `tls_cert` / `tls_key` | `true` / — / — | самоподписанный или свой сертификат |
| `behind_proxy` | `false` | за nginx/haproxy на этом же хосте (тогда `listen` только loopback) |
| `allowed_networks` | локальные и частные сети | откуда разрешены подключения; `[]` — отовсюду |
| `cbsd_command`, `initenv_command` | через `sudo -n` | как вызывать CBSD |
| `workdir`, `dist_dir` | авто, `/usr/local/cbsd` | каталоги CBSD |
| `session_idle_minutes`, `session_max_hours` | 30, 12 | сессии |
| `max_concurrent_jobs`, `command_timeout_minutes` | 4, 120 | задачи |
| `terminal_role` | `admin` | кому доступен терминал: `admin`, `operator` или `disabled` |
| `terminal_idle_minutes` | 30 | закрывать терминал без активности |
| `iso_max_size_gb` | 32 | наибольший размер ISO при загрузке и скачивании |
| `iso_fetch_allow_private` | `false` | разрешить скачивание ISO с адресов локальной сети |

ISO-образы хранятся в `<workdir>/src/iso/upload` (каталог создаёт `install.sh`, владелец `cbsdweb`). Если перед cbsd-web стоит nginx, увеличьте для него `client_max_body_size` и `proxy_request_buffering off`, иначе большие ISO не пройдут.

Обычный HTTP без TLS разрешён только на loopback-адресе.

## Разработка без FreeBSD

```sh
make test     # модульные и интеграционные тесты (поддельный cbsd, тестовые SQLite-базы)
make dev      # http://127.0.0.1:8099, вход admin / dev-password-1
```

`make dev` создаёт фиктивный workdir (`tools/devfixture`) и подставляет `testdata/fake-cbsd`, который печатает команды вместо выполнения.

## Структура

```
cmd/cbsd-web/        точка входа и CLI (serve, useradd, users, userdel, check)
internal/server/     HTTP: маршруты, middleware безопасности, обработчики, TLS, статика
internal/cbsd/       чтение баз CBSD, профили ВМ, проверка аргументов, запуск cbsd
internal/auth/       пользователи (bcrypt), сессии, CSRF, защита от перебора
internal/jobs/       фоновые задачи с трансляцией вывода
internal/audit/      журнал аудита
web/static/          интерфейс (index.html, app.js, app.css; vendor/ — xterm.js 5.5.0 (MIT), noVNC 1.7.0 (MPL-2.0))
deploy/              rc.d-скрипт, sudoers, пример конфига
scripts/install.sh   установщик для FreeBSD
```

## Ограничения текущей версии

* Тонкая настройка дисков, сетевых карт и проброса PCI для ВМ пока делается в консоли (`cbsd bconfig`). Для клеток не редактируются структурные параметры (path, data, rcconf, basename, emulator, zfs_encryption): их безопасно менять только из консоли.
* Трафик клетки виден, только если у неё VNET: без VNET она работает на адресах интерфейса хоста.
* Лимиты rctl работают, только если в `/boot/loader.conf` есть `kern.racct.enable=1`.
* QEMU и VirtualBox в интерфейсе пока не поддерживаются.
* Проверено на тестовом стенде с поддельным `cbsd`; на реальном FreeBSD-хосте интерфейс ещё не запускался.
